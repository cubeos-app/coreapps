# Constitution — CubeOS Coreapps

Component repo of the CubeOS project. Inherits all 19 parent Articles from `cubeos/docs/constitution.md`.

## Article C-I — Every coreapp ships as `<name>/appconfig/docker-compose.yml`

Each top-level directory under `coreapps/` represents ONE coreapp. Its single source of truth is `<name>/appconfig/docker-compose.yml`. Additional config (env files, volume seeds, init scripts) lives under `<name>/appconfig/` or `<name>/data-templates/`.

`ci-deploy.sh` rsyncs the entire `<name>/` tree to `/cubeos/coreapps/<name>/` on the target Pi.

## Article C-II — `image:` references MUST point to `localhost:5000`

Every `image:` line in every coreapp's compose file MUST reference `localhost:5000/cubeos-app/<name>:<tag>`. Never `docker.io/`, never `ghcr.io/`, never any external registry at deploy time. The local registry coreapp (`coreapps/registry/`) is the authority.

This satisfies parent Article XIV (local registry pull discipline). The build pipeline (in `releases/`) pre-fetches everything via `skopeo` and seeds the local registry during image build.

## Article C-III — Image tags pinned via `image-versions.env`

The `image-versions.env` file at the repo root declares every coreapp's tag (`API_TAG`, `HAL_TAG`, `DASHBOARD_TAG`, etc.). Each compose file references `${<NAME>_TAG:-latest}`. CI sets the env when deploying.

Changing a coreapp version is a one-line PR against `image-versions.env`.

## Article C-IV — Self-healing watchdog is mandatory infrastructure

`scripts/cubeos-watchdog.service` (systemd) + `scripts/cubeos-watchdog.timer` run `scripts/watchdog-health.sh` every 5 min. The watchdog checks: docker daemon up, swarm leader present, every advertised coreapp service running, every healthcheck green. On failure: log + auto-restart the offending service.

Watchdog is installed at first boot via `scripts/install-watchdog.sh` (called by releases firstboot).

## Article C-V — Smoke test is the DoD on every PR

`scripts/smoke-test.sh` validates: every compose file parses, every `image:` is localhost:5000-prefixed, every service has a healthcheck, every volume mount has a Pi-existing target path. CI runs `smoke-test.sh --check-only` on every PR.

## Article C-VI — Defaults via `defaults.env`; secrets via firstboot

`defaults.env` carries non-secret defaults consumed by compose files (timezone, log levels, default ports). Secrets (JWT keys, DB passwords) come from `/etc/cubeos/secrets.env` generated by `releases/firstboot/cubeos-generate-secrets.sh`. The two files MUST NEVER overlap (smoke test enforces).

## Article C-VII — Deletion is explicit

When a coreapp is removed from git, `ci-deploy.sh` MUST tear down its swarm service AND prune its `/cubeos/coreapps/<name>/` directory from the Pi (after rsync diff detection). Stale directories cause confusion at the next watchdog run.

## Article C-VIII — Per-coreapp READMEs are mandatory

Each `coreapps/<name>/README.md` MUST cover: what the app does, what port it listens on, what volumes it mounts, what dependencies (other coreapps or host services) it needs. PR linter checks for the README's presence + section headers.
